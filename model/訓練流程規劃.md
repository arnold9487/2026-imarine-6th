## 1. 資料層

### 1.1 來源與切分

- SeaFront:遊戲引擎模擬吊具起吊貨櫃,每場景 4 個相機視角(兩長邊 + 兩端面),共 2,472 場景 × 4 = 9,888 張。
- 標注來源用 `bbannotation/`(YOLO txt:`類別 中心x 中心y 寬 高`,全部歸一化到 0~1)。
- **場景級切分**:沿用官方 train/val,但同場景 4 張絕不跨切分(唯一跨切分場景整組歸 train)→ 7,912 / 1,976。
  - 為什麼重要:同場景 4 張只是視角不同,若一張在 train 一張在 val,等於考題先看過(資料洩漏),val 分數會虛高。

### 1.2 類別設計:5 類 → 2 類

原始 5 類:container / axis(底樑彎曲)/ concave(凹陷)/ dentado(撞痕)/ perforation(穿孔)。
四種破損合併為單一 `damage`,理由:

1. RPS 只需要「損壞機率」,不需要破損分型;
2. 合併後 damage 樣本量 ×4(約 2,865 個實例),對抗類別不平衡;
3. 破損分型的邊界(concave vs dentado)連人眼都難分,強行分類會拉低整體。

保留 `container` 類的價值:推論時可用「damage 框是否落在 container 框內」過濾背景誤報,也讓模型學到「先找到櫃、再找櫃上的破損」的空間關係。

### 1.3 已知侷限(寫改進方向時的素材)

- 構圖固定:吊具視角、貨櫃置中佔滿畫面 → 模型只在此構圖下可靠。
- 破損佔比小:多數破損只佔畫面 2~5%。
- 渲染材質與真實紋理有域差(實驗 1 已證實這是主要 gap)。

## 2. 模型架構:YOLO11s

總量:182 層、943 萬參數、21.6 GFLOPs。輸入 640×640×3。三段式:

### 2.1 Backbone(特徵提取,層 0~10)

```
層  模組         輸出通道  解析度     說明
0   Conv 3×3/s2    32     320×320   stem,先降採樣
1   Conv 3×3/s2    64     160×160
2   C3k2          128     160×160   ← CSP 殘差塊
3   Conv 3×3/s2   128      80×80    ← P3 尺度
4   C3k2          256      80×80
5   Conv 3×3/s2   256      40×40    ← P4 尺度
6   C3k2          256      40×40
7   Conv 3×3/s2   512      20×20    ← P5 尺度
8   C3k2          512      20×20
9   SPPF          512      20×20    ← 空間金字塔池化
10  C2PSA         512      20×20    ← 空間注意力
```

- **Conv**:卷積 + BatchNorm + SiLU 激活。stride 2 的卷積同時做降採樣(取代 pooling)。
- **C3k2**(CSP 瓶頸塊):把輸入通道分兩路,一路走殘差瓶頸(兩層小卷積 + 跳接),一路直通,最後拼接。跳接讓梯度能直達淺層(深網路不退化),分流省一半計算。
- **SPPF**(空間金字塔池化):同一特徵圖連續過三次 5×5 MaxPool 再拼接,等效一次看 5/9/13 大小的感受野——讓 20×20 的每一格同時擁有「多種範圍的上下文」。
- **C2PSA**(位置自注意力):讓 20×20 特徵圖上任意兩格互相「對話」(注意力加權),補足卷積只看局部的缺陷,對「破損在櫃體上的相對位置」這類全局關係有幫助。這是 YOLO11 相對 YOLOv8 的主要新增。

### 2.2 Neck(特徵金字塔,層 11~22):FPN + PAN

問題:深層(20×20)語意強但丟了細節,淺層(80×80)細節多但不懂語意。解法是雙向融合:

- **自上而下(FPN)**:P5 上採樣×2 與 P4 拼接 → C3k2 → 再上採樣與 P3 拼接 → C3k2。把「這是破損」的語意灌給高解析度層。
- **自下而上(PAN)**:融合後的 P3 再逐級降採樣拼回 P4、P5。把精確的定位細節送回深層。

產出三張最終特徵圖:P3(80×80×128,管小物件)、P4(40×40×256,中)、P5(20×20×512,大)。

### 2.3 Head(偵測頭,層 23):anchor-free + DFL

三張特徵圖的**每一格**(80²+40²+20² = 8,400 格)各自預測:

1. **類別分支**:2 個 logit(container、damage),各自過 sigmoid → 獨立的 0~1 信心。**沒有獨立的 objectness**,類別分數即信心值——這就是推論輸出 `conf` 的來源。
2. **框回歸分支(DFL)**:不直接回歸「上下左右距離」四個數,而是把每個距離離散成 **16 個 bin 的機率分布**,期望值 = 最終距離。好處:模型能表達「這條邊大概在這附近」的不確定性,邊界模糊(破損正是如此)時比單點回歸穩。
3. anchor-free:每格直接以自身位置為錨點預測,不需要預設 anchor 尺寸(舊 YOLO 要調 anchor,現在免了)。

推論後處理:8,400 個候選 → 信心門檻過濾 → **NMS**(同類別重疊框只留信心最高者,IoU 門檻 0.7)→ 最終輸出。

## 3. 訓練機制

### 3.1 遷移學習

`YOLO("yolo11s.pt")` 載入 COCO(33 萬張真實照片、80 類)預訓練權重,499 個權重張量成功轉移 493 個(偵測頭最後一層因類別數 80→2 而重建)。意義:底層的邊緣/紋理/形狀偵測器直接繼承,只需教會「貨櫃與破損」。**這也是模型唯一的真實世界知識來源**——改進時不要輕易破壞它(見 §6)。

### 3.2 Optimizer(實際訓練日誌)

設 `optimizer=auto`,ultralytics 實際選了:

```
MuSGD(lr=0.01, momentum=0.9)
參數分組:81 組 weight(decay=0)、88 組 weight(decay≈4.7e-4)、87 組 bias(decay=0)
```

- **SGD + momentum 家族**:每步沿梯度反方向走,momentum 0.9 = 保留九成上一步的速度(慣性),抹平單一 batch 的噪聲。MuSGD 是 ultralytics 8.4 的變體(對部分層混入 Muon 式正交化更新,收斂更穩)。
- **參數分組的意義**:weight decay(權重衰減,防過擬合的 L2 拉力)只施加在卷積權重上;BatchNorm 參數與 bias 不衰減(衰減它們會傷害歸一化統計,是標準做法)。
- **學習率排程**:前 3 個 epoch warmup(從近 0 升到 0.01,避免一開始大步走毀掉預訓練權重),之後線性衰減到 lr0×0.01 = 1e-4。
- **EMA**:訓練全程維護一份「權重的指數移動平均」,val 與 best.pt 用的是這份平滑版權重,比瞬時權重穩。

### 3.3 訓練迴圈與停止

- batch:`-1` 自動探測 VRAM(5070 12GB 約 32);AMP 混合精度(半精度算、全精度存,省一半視訊記憶體、快 1.5~2 倍)。
- 60 epochs,`patience=15`:連續 15 epoch fitness 無進步提前停。
- **fitness = 0.1×mAP50 + 0.9×mAP50-95**:best.pt 是 fitness 最高那個 epoch 的 EMA 權重,不是最後一個 epoch。

### 3.4 損失函數(三項加權和)

每個 batch:`Loss = 7.5×box + 0.5×cls + 1.5×dfl`

先講**正樣本分配(TAL, Task-Aligned Assigner)**——「8,400 格裡誰該對這個標注框負責」:
對每個標注框,計算每一格的對齊度 `t = cls_score^α × IoU^β`,取 top-10 格當正樣本。意義:**只有「分類猜得好 且 框畫得準」的格子才領到學習任務**,分類與定位不脫節。其餘格子只學「這裡沒東西」。

1. **cls loss(BCE,權重 0.5)**:每格每類獨立的二元交叉熵。你熟的公式:`-[y·log(p) + (1-y)·log(1-p)]`,猜錯且很自信時罰最重。
2. **box loss(CIoU,權重 7.5)**:1 − IoU,再加兩個罰項:中心點距離、長寬比差異。純 IoU 在兩框不相交時梯度為零(不知往哪修),CIoU 的距離項保證永遠有方向感。權重 7.5 最大——定位是偵測的本體。
3. **dfl loss(權重 1.5)**:對 16-bin 分布做交叉熵,拉高「真實距離落點附近兩個 bin」的機率。與 box loss 配合:box 管期望值對不對,dfl 管分布形狀尖不尖。

### 3.5 資料增強(train.py 實際設定)

| 增強 | 值 | 對抗什麼 |
|---|---|---|
| hsv_h/s/v | 0.02 / 0.8 / 0.5 | 合成圖光照太乾淨、色彩太一致 |
| degrees / translate | ±5° / 0.15 | 相機角度與構圖固定 |
| scale | ±0.5(0.5~1.5 倍) | 破損大小單一 |
| fliplr | 0.5 | 視角多樣性(免費翻倍) |
| mosaic | 1.0(最後 10 epoch 關) | 四圖拼一張:打破「貨櫃永遠置中」,製造尺度與脈絡混合 |
| mixup | 0.1 | 兩圖疊加,輕度正則化 |

每張圖每個 epoch 被隨機「折磨」出不同版本 → 60 epochs 等於看過 60 種變體,逼模型學破損本質而非背圖。

## 4. 評估指標(讀 runs 輸出用)

- **Precision**:框出來的裡面多少是真的(damage 0.925 → 誤報率低)。
- **Recall**:真的破損抓到多少(damage 0.729 → 每 4 個漏 1 個,是目前主要短板)。
- **mAP@50**:IoU>0.5 算命中,掃過所有信心門檻畫 P-R 曲線取面積。單一數字總結「P 和 R 的整體權衡」。
- **mAP@50-95**:IoU 門檻從 0.5 到 0.95 每 0.05 一檔取平均——考「框得多貼」。
- P 高 R 低的組合(0.925/0.729)意味著:**調低信心門檻可以用少量誤報換回漏檢**,這對 RPS 是划算的交易(漏檢成本 >> 誤報成本),見 §5.3。

## 5. 推論輸出與 RPS 嫁接(最重要的一節)

### 5.1 程式層面的輸出類型

```python
from ultralytics import YOLO
model = YOLO(r"runs\damage_yolo11s\weights\best.pt")
results = model.predict("某張圖.jpg", conf=0.15, imgsz=640)

r = results[0]
r.boxes.cls    # Tensor[N] 類別 id:0=container, 1=damage
r.boxes.conf   # Tensor[N] 信心值 0~1
r.boxes.xyxy   # Tensor[N,4] 像素座標 (x1,y1,x2,y2) 左上/右下
r.boxes.xywhn  # Tensor[N,4] 歸一化中心格式(要畫在網頁上用這個最方便)
r.save("畫框圖.jpg")           # 存視覺化
json_str = r.to_json()         # 直接轉 JSON(含類別名、信心、座標)
```

### 5.2 從 conf 到 P_i(單櫃損壞機率)

一張圖可能有 0~N 個 damage 框,RPS 需要的是「這櫃損壞機率 P_i」一個數。三種映射:

| 方案 | 公式 | 特性 |
|---|---|---|
| 最大值(建議起手) | `P_i = max(conf)` | 保守、可解釋:「最可疑的那個破損有多可疑」 |
| 聯合機率 | `P_i = 1 − Π(1−conf_j)` | 多處破損會疊加(3 個 0.5 → 0.875),呼應「規模」精神 |
| 面積加權 | `P_i = Σ(conf_j × area_j) / area_櫃` | 額外攜帶嚴重度資訊,可當 severity 的雛形 |

**重要注意**:conf 是分類器輸出,**不是校準過的機率**——conf 0.8 不等於「80% 機率真的壞」。Demo 階段直接用無妨(排序用途只要單調性),但要寫進改進方向:用驗證集做**校準**(temperature scaling / Platt),讓 D_score = Σ P_i 的「期望損壞數」解釋在統計上站得住。答詢若被問到,誠實說「目前作排序用,校準是上線前的必要步驟」。

### 5.3 信心門檻怎麼選

- 門檻高(0.5+):P 更高、R 更低 → 適合「警報要少而準」。
- 門檻低(0.15~0.25):撈回漏檢、多些誤報 → **適合 RPS**,因為 β 和加總會稀釋單一誤報,而漏掉高風險櫃是系統性失敗。
- 建議:demo 用 0.25;把門檻做成系統參數,答詢時展示「這是管理者可調的風險偏好旋鈕」。

### 5.4 建議的嫁接介面(inspections.json)

```json
{
  "inspections": [
    {
      "container_id": "OOLU1170380",
      "ct": "CT5",
      "ts": "2025-08-14T02:00:00+08:00",
      "p_damage": 0.87,
      "boxes": [
        {"cls": "damage", "conf": 0.87, "xywhn": [0.62, 0.41, 0.18, 0.22]}
      ],
      "img": "inspections/OOLU1170380_pred.jpg"
    }
  ]
}
```

網站端流程:讀此檔 → 按 ct+時段聚合 `D_score = Σ p_damage` → `RPS = (小船等量/Limit) × (1 + β × D_score)` → 排名榜重排 + 地圖警報圖標。**Demo 版此檔寫死即可**(拿 runs 裡的合成圖推論結果編幾筆),未來換成即時推論服務(Flask/FastAPI 包 model.predict,或匯出 ONNX 給非 Python 環境)只是資料來源替換,前端不用動——這就是計畫書說的「標準化整合接口」。

## 6. 改進方向的掛鉤清單(供你展開)

| 方向 | 動什麼 | 預期效果 / 風險 |
|---|---|---|
| 拉高 Recall | 降 conf 門檻、cls 權重 0.5→1.0、或訓練時 oversample 含破損場景 | 漏檢 27%→? 換少量誤報,對 RPS 划算 |
| 模型放大 | yolo11s → 11m / 11l | 合成域 +2~4 mAP,推論仍 <5ms;VRAM 需求升 |
| 解析度 | imgsz 640→960(訓練與推論一致) | 小破損受益;訓練時間 ×2 |
| conf 校準 | 驗證集上 temperature scaling | D_score 有統計意義,不改模型 |
| 升級分割 | YOLO11s-seg + SeaFront 的 COCO polygon(現成) | 得到破損**面積** → severity 權重進 D_score |
| 凍結骨幹 | freeze 前 N 層再訓 | 保住 COCO 真實紋理知識(實驗 1 教訓) |
| 資料飛輪 | 部署後回收影像 → 偽標籤 → 滾動再訓 | 計畫書已承諾的路線,閉環自我迭代 |
| TTA / 雙模型聯集 | 推論期增強投票 / baseline+zoom 取聯集 | 零訓練成本換召回,推論時間 ×2~3 |
