# 決賽故事線 — 智慧貨櫃動態風險巡檢決策系統

> 依據:預賽正式計畫書(第六屆航港大數據創意應用競賽提交版)+ 決賽評分(創新 30%、應用落實 25%、分析合理 25%、AI 工具 10%、簡報答詢 10%)。

## 決賽最強的一張牌:兌現預賽的承諾

預賽計畫書裡,雙軌架構的四個階段有三個標注「實作完成」,唯獨**階段三(AI 殘損辨識)寫的是「預想藍圖與機制」**。決賽開場就要打這張牌:

> 「兩個月前我們向評審承諾了一張藍圖;今天,藍圖上最後一塊拼圖已經完成——我們用文獻實證的合成資料訓練出 YOLO 破損偵測模型,damage mAP@50 = 0.79、貨櫃本體 99.5%、單張推論 0.8 毫秒。預賽的雙軌,決賽已合流。」

這直接命中決賽評分從「概念可行性」(預賽 25%)轉向「**應用落實性及成效**」(決賽 25%)的轉變:別隊講計畫,你們講**進度**。

## 動機鏈(照計畫書的痛點,講成必然)

1. **結構性背景**:後疫情人力斷層 + 航運業「三重夾擊深度調整期」(航港局 115Q1 海運分析)→ 基層驗櫃人力被極致壓縮。
2. **痛點一(何時漏檢)**:尖峰時段吊裝節奏快,理貨員疲勞漏檢;且現場車陣穿梭有致命工安死角(曾有驗櫃員遭貨櫃車撞擊)。
3. **痛點二(責任斷層)**:橋式機、拖車、貨輪分屬不同代理商,FOB→FCA 趨勢下 CY 交接點的權責更敏感;漏檢又無數位存證 → 理賠糾紛。
4. **兩個痛點各自長出一軌**:
   - 忙碌是可量化的 → **PPI 港口壅塞壓力指標**(TPNET 全年進出港 XML + 掃描線演算法 + 自適應上限)
   - 看櫃是可自動化的 → **AI 破損辨識**(合成資料攻克樣本稀缺,Delgado 2023 背書)
5. **融合(RPS)**:單軌都會誤判——只看壓力,低壓時段的高風險櫃會被忽略;只看破損,警報在尖峰時段會被淹沒。所以用決策級融合(Hall & Llinas, 2001)把兩軌交織成**風險巡檢分數**,回答「哪裡先檢、何時先檢、人力怎麼配」。

> 修辭原則:不說「我們做了兩個東西」,說「兩個痛點各自長出一軌,RPS 把它們接回同一個決策」。

## 核心公式與兩條推論路徑(分析合理性 25% 的主戰場)

```
RPS = ( 當前靠泊小船等量 / 自適應上限 Limit ) × ( 1 + β × D_score )
        └────────── PPI 壅塞項 ──────────┘   └── 殘損風險放大項 ──┘

D_score = Σ P_i(該中心所有進港貨櫃的損壞機率加總)、β ≈ 0.1
```

講這條公式時的三個關鍵論點(答詢必考):

1. **為什麼 D_score 用加總不用最大值**:1 個 98% 損壞的櫃 vs 100 個 50% 損壞的櫃——後者需要調動整個車隊,前者一人一車。加總同時捕捉「機率」與「規模」,這是資源調度視角,不是單櫃視角。
2. **為什麼是 (1 + β·D_score) 而不是直接相乘**:沒有破損警報時 RPS 退化為純 PPI(系統仍有用);有警報時做非線性放大。100 個 50% 的櫃 → 放大 6 倍,壓力排名瞬間衝頂。
3. **兩條推論路徑**(計畫書原文,簡報各給一個情境動畫/畫面):
   - **常態尖峰推論(壅塞驅動)**:預定靠泊大增 → PPI 衝高 → 排名前移 → 提前派駐驗櫃員與設備。
   - **極端風險推論(殘損驅動)**:車船稀少、PPI 低,但邊緣相機偵測到某批櫃 P_damage 飆高 → 放大項引爆 RPS → 低壓時段也能觸發高風險預警。**這條是「雙模態不可拆」的證明**:任何單軌系統都抓不到這個情境。

理論支柱一句話帶過即可:排隊理論/卜瓦松流(Kleinrock, 1975)撐 PPI 上限的科學性;多模態決策級融合(Hall & Llinas, 2001)撐 RPS 的架構正當性。

## Demo 整合方案(決賽展示建議)

網站已有 PPI 全部功能(時間滑桿、預測虛線、懸浮明細、點船彈窗)。決賽加一個「**巡檢模式**」展示層,工作量約 1~2 天:

1. 挑 10~20 張辨識模型的實際輸出圖(有框、有信心值)。
2. 寫死一個 `inspections.json`:模擬這批櫃在某些時刻到達某些 CT。
3. 地圖上該 CT 出現警報圖標;點開顯示:辨識結果圖 + P_damage + 當下 PPI + **算出來的 RPS**,右側排名榜即時重排。
4. **高潮一幕**:拖時間軸演「極端風險推論」——深夜 CT5 壓力墊底,一批高 P_damage 櫃進港,RPS 排名瞬間衝第一。這 10 秒鐘就是整份計畫書的靈魂可視化。

(若時間不夠,退而求其次:投影片上用真實數字演算一次 RPS,兩情境對比。)

## 10 分鐘簡報流(建議 11 頁)

1. **開場 40 秒·場景**:尖峰午後 CT5,理貨員每櫃 12 秒;三天後目的港發現穿孔,三個代理商互指,無存證。(痛點一+二一幕演完)
2. **問題拆解**:漏檢 = 忙(何時何地)×看不到(這櫃有沒有)→ 兩軌架構圖。
3. **PPI 這一軌**(2 頁):資料工程亮點一頁(TPNET 跨月採集、regex 修復毀損 XML、VISA_NO 雙向配對、貨櫃碼頭過濾矩陣)+ 統計一頁(掃描線、小船等量權重、分散指數自動切換 99.85% 上限)。
4. **網站 Demo**(現場操作 90 秒):滑桿看尖峰、虛線預測、懸浮 CT 明細。
5. **辨識這一軌**(2 頁):樣本稀缺是業界結構性困境(理賠檔案=商業機密)→ 合成資料策略(Delgado 2023《TR Part E》實證可行 + Nguyen 2025 數位孿生瑕疵)→ **成果數字:mAP 0.79 / 99.5% / 0.8ms** + 辨識結果圖。
6. **RPS 融合**(2 頁):公式一頁(D_score 加總邏輯 + 放大項)、兩條推論路徑一頁 → 切回 Demo 演「極端風險」那一幕。
7. **未來藍圖 40 秒**:資料飛輪(部署後持續回收真實影像滾動再訓練)、氣象大數據修正 ETA、即時到港流升級實時看板 → 對接 PortXchange 式的中立資訊平台願景。
8. **結尾一句**:「預賽我們交出藍圖,決賽我們交出系統;下一步,交給港區的每一台相機。」

時間分配:痛點 1.5 分、PPI 2.5 分(含 demo)、辨識 2 分、RPS+融合 demo 2.5 分、未來+結尾 1.5 分。

## 預期答詢 Q&A

| 問題 | 回答要點 |
|---|---|
| 壓力跟破損有什麼關係? | 壓力不造成破損,壓力造成**漏檢**。RPS 融合的是「檢查資源的風險排序」,不是破損成因。 |
| 模型沒在真實照片驗證過? | 誠實三段:①合成 val 是受控考卷(部署視角的真實資料不存在公開來源,這正是 Delgado 2023 指出的業界困境);②文獻已實證合成訓練可泛化至真實港口場景;③架構預留資料飛輪——部署即開始回收真實影像滾動微調,這是分階段路線圖,不是缺口。 |
| β 怎麼定?0.1 有依據嗎? | 可解釋的初始值,設計原則是「百櫃級異常要能製造數倍放大」;上線後以歷史複核紀錄回歸校準。刻意不用黑箱,管理者看得懂才敢用。 |
| D_score 會不會被誤報灌爆? | 信心門檻先濾一層;且 β 讓放大平滑而非階躍;誤報成本(多派一次檢)遠低於漏檢成本(理賠+工安),此為風險不對稱下的合理偏保守設計。 |
| iMarine 用在哪? | 理論起點(24h 泊靠分析、裝卸量統計選定高雄港)+ 科普專題的 IoT/數位孿生願景呼應;顆粒度不足處以 TPNET 延伸加值——「從 iMarine 出發、向下鑽深」正是資料庫加值的示範。 |
| 為什麼 CT 級不做單櫃級? | 巡檢人力按貨櫃中心配置,決策粒度對齊資源粒度;單櫃級資訊保留在警報明細裡,沒有丟失。 |

## 一定要避免的講法

- ❌「我們沒能力蒐集真實資料」→ ✅「破損影像鎖在各航商理賠檔案裡,是業界結構性困境(文獻同此觀點)」
- ❌ 把 mAP 當主角展開實驗細節 → 數字一頁帶過,重心放發想與 RPS 融合
- ❌ 說即時串流/邊緣相機「已實作」→ 說「架構已預留標準化接口」(計畫書原話)
- ❌ 兩個 demo 分開講完就結束 → 一定要用「極端風險推論」那一幕證明**雙模態不可拆**
